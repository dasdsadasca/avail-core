# Avail Core Protocol: Glossary of Terms

This glossary provides definitions for important terms and concepts specific to the Avail core protocol, based on its codebase and documentation.

| Term                          | Definition                                                                                                                                                                                                                                                           |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AppId`                       | An identifier (typically a unique number) for an application submitting data to the Avail chain. Used to differentiate data from various sources and facilitate lookups via `app_lookup`.                                                                        |
| `AppExtrinsic`                | A specialized extrinsic format in Avail that wraps raw application data (`data: Vec<u8>`) along with its corresponding `app_id`. It's the primary way applications submit their data to be made available.                                                          |
| `DaBlock`                     | The fundamental block structure in Avail (short for Data Availability Block). It's a generic container holding a `Header` (with DA extensions) and a list of `Extrinsic`s (including `AppExtrinsic`s).                                                              |
| `Header` (Avail Context)      | The block header in Avail. It contains standard Substrate header fields (parent hash, block number, state root, etc.) plus a crucial `extension` field (`HeaderExtension`) for Avail-specific data availability metadata.                                          |
| `HeaderExtension`             | An enum within the Avail `Header` designed to encapsulate versioned data availability-specific metadata. Currently, `V3(v3::HeaderExtension)` is the primary variant.                                                                                               |
| `v3::HeaderExtension`         | Version 3 of the header extension. It directly contains the `app_lookup` structure and the `KateCommitment` for the block's data.                                                                                                                                  |
| `KateCommitment`              | (Specifically `v3::KateCommitment`) A structure embedded in the `v3::HeaderExtension` containing all information for Avail's Kate polynomial commitment scheme. It includes `rows`, `cols`, the serialized Kate `commitment` points, and a `data_root`.             |
| `DataRoot` (in `KateCommitment`) | A Merkle root (`H256`) within the `KateCommitment` struct. It represents the root hash of all original submitted data *before* it's arranged into the 2D matrix and erasure-coded. This root must match the `BlobRoot` from `TxDataRoots`.                      |
| `BlobRoot`                    | A Merkle root (`H256`) within the `TxDataRoots` structure. It specifically commits to the set of all general-purpose application data ("blobs") submitted to the chain in a block, typically via `AppExtrinsic`s.                                                  |
| `BridgeRoot`                  | A Merkle root (`H256`) within the `TxDataRoots` structure. It commits to data specifically designated for or received from bridges connecting Avail to other blockchains (e.g., Ethereum).                                                                         |
| `DataRoot` (in `TxDataRoots`) | A global Merkle root (`H256`) within the `TxDataRoots` structure. It's typically a combined hash (e.g., `keccak_256(BlobRoot, BridgeRoot)`) providing a single top-level commitment to all data categories covered by `TxDataRoots`.                                |
| `TxDataRoots`                 | A structure that aggregates different Merkle roots related to the data in a block: `DataRoot` (global), `BlobRoot` (for application data), and `BridgeRoot` (for bridged data).                                                                                 |
| `DataProof`                   | A Merkle proof structure used to demonstrate the inclusion of a specific piece of data (a "leaf" hash) within a larger dataset committed to by a Merkle root (typically `BlobRoot` or `BridgeRoot` from `TxDataRoots`).                                            |
| `Cell` (Kate Matrix Context)  | A single unit of data at specific coordinates `(row, col)` within the 2D data matrix used for Kate commitments. Each `Cell` contains a fragment of the original block data after it has been potentially erasure-coded and arranged for commitment.          |
| `Kate Proof` (Conceptual)     | A cryptographic witness for a specific `Cell` in the data matrix. It allows verification that the `Cell`'s content is consistent with the overall `KateCommitment` (the set of polynomial commitment points) published in the block header. Used in DAS.          |
| `Data Availability Sampling (DAS)` | The process by which light clients verify data availability. They randomly request `Cell`s (and their `Kate Proof`s) from the data matrix and verify them against the `KateCommitment` in the block header.                                                        |
| `app_lookup`                  | A data structure within the `v3::HeaderExtension`. It provides a lookup mechanism (e.g., a map or index) that links `AppId`s to information about their corresponding data's location or indices within the block's data layout, aiding efficient retrieval. |
| `Rows` (in `KateCommitment`)  | The number of rows in the 2D data matrix used for Kate commitments, as specified in the `KateCommitment` struct.                                                                                                                                               |
| `Cols` (in `KateCommitment`)  | The number of columns in the 2D data matrix used for Kate commitments, as specified in the `KateCommitment` struct. The product `Rows * Cols` gives the total cells in the matrix.                                                                            |
| `BlockId`                     | An enum used to identify a block, either by its hash (`BlockId::Hash`) or its number (`BlockId::Number`). Defined in `core/src/da_block.rs`.                                                                                                                       |
| `SignedBlock`                 | A structure that pairs a full `DaBlock` with its `Justifications` (cryptographic proof of finality or consensus agreement). Defined in `core/src/da_block.rs`.                                                                                                      |
| `BoundedData`                 | A type alias for `BoundedVec<u8, ConstU32<MAX_LEN>>`, representing a vector of bytes with a compile-time maximum length. Used in `core/src/data_proof.rs`, often in the context of data sent to/from bridges with size limitations.                           |
| `ExtendedBlock` Trait         | An Avail-specific trait (`core/src/traits/extended_block.rs`) implemented by `DaBlock`. It likely provides an interface to access Avail-specific block properties, such as the `ExtendedHeader`.                                                                |
| `ExtendedHeader` Trait        | An Avail-specific trait (`core/src/traits/extended_header.rs`) implemented by Avail's `Header`. It provides methods to access the `HeaderExtension` containing DA-specific metadata.                                                                             |
